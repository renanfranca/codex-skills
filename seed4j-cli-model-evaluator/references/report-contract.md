# Report and evidence contract

Write both documents in English. Preserve the source prompt verbatim. Identify its language and add a reader-only English translation when it is not English; never use the translation as experimental input.

## README.md

Keep README concise and include:

1. experiment purpose and non-causal framing;
2. exact shared prompt, language, and translation when needed;
3. controlled conditions and changed variables;
4. branch/model/effort/pinned-result matrix;
5. principal findings and a link to `MODEL_EVALUATION.md`;
6. **Try Seed4J CLI Yourself**, with observed pinned CLI/runtime, prerequisites, pinned and latest-unpinned installation examples, local skill installation, branch-per-run rules, and validation steps;
7. authoritative links to the Seed4J CLI repository and OpenAI skills documentation.

Explain that a newer CLI/runtime or changed skill is a new experiment, not an exact reproduction. A reproduction starts from the base specification branch, uses a new branch and Codex task per run, freezes one prompt, and does not expose prior implementation content to the new task.

## MODEL_EVALUATION.md

Include:

1. objective, scope, and methodology;
2. common base and immutable specification;
3. controlled conditions, frozen prompt, model matrix, and sequential order;
4. acceptance protocol and the complete point allocation committed before result inspection;
5. per-run Seed4J discovery, help, plan, apply commands, parameters, module order/history, wrapper/build files, exact source/test paths, native verification, and common acceptance results;
6. requirement-level and criterion-level deductions with immutable evidence;
7. same-model effort comparisons, same-effort model comparisons, then aggregate scorecard;
8. final implementation overview and relevant design observations;
9. unweighted timing, size, token/cost availability, and transcript/audit appendix;
10. limitations: cache warming, sequential order, host dependence, transcript schema/format differences, shared-remote discoverability, and unavailable data;
11. detailed reproduction appendix.

Document the Seed4J skill tree hash and each pinned version. Do not call output generated by the model independent ground truth.

## Link policy

- Link living branch names to `/tree/<url-encoded-branch>` for navigation.
- Link every claim-bearing commit and artifact through the full immutable commit SHA: `/commit/<full-sha>`, `/blob/<full-sha>/<path>`, or `/tree/<full-sha>/<path>`.
- Link `main`, the common base commit, base branch, pinned `SPEC.md`, every audit head, every implementation commit, `.seed4j/modules` record, build file, wrapper, production source, test, transcript, and manifest at its first meaningful occurrence or audit table.
- Keep labels short and readable; do not repeat links in nearby prose when an evidence table already anchors the claim.
- Use authoritative external documentation only. Do not link search results.
- Verify local existence with the exact pinned object before publishing each URL.

## Reproduction integrity

The reproduction appendix must distinguish the observed pinned CLI/runtime from the latest unpinned CLI. It must show:

- cloning the public experiment repository;
- creating a fresh branch directly from the frozen base branch;
- confirming `.agents/skills/seed4j-cli` and activating repository-local skills by starting/restarting Codex at the repository root;
- choosing a new model/effort, using the exact original prompt, and creating a new task;
- running native verification, inspecting Git and `.seed4j/modules`, and optionally repeating the public acceptance harness.

Do not add the Seed4J skill to `main`; the reproduction uses the frozen base branch.

## Delivery boundary

The evaluation branch adds exactly `README.md`, `MODEL_EVALUATION.md`, and the full Apache License 2.0 `LICENSE` relative to `origin/main`. It may contain an early protocol commit and one final report commit. It must not change `SPEC.md`, implementation branches, tags, releases, or repository settings. Open the PR but do not merge it.
